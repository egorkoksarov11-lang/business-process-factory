# Business Process Factory

Репозиторий управления конвейером анализа интервью, моделирования AS-IS, проектирования TO-BE и выпуска процессных схем и приложений.

Основной принцип: **GitHub хранит источник истины о процессе; чаты и агенты являются исполнителями стадий конвейера, а не владельцами контекста.**

## Что находится в репозитории

- `AGENTS.md` — единая точка входа для всех агентных чатов.
- `governance/` — правила процесса, архитектуры, качества и изменений.
- `agents/` — инструкции четырём осмысленным рабочим ролям.
- `templates/` — шаблоны Process Package, реестров и журналов.
- `sources/` — правила хранения исходных интервью и иных свидетельств.
- `processes/` — рабочие пакеты отдельных процессов.
- `views/` — сквозные карты, карты функций ролей и подразделений.
- `examples/` — эталонные примеры оформления.

## Конвейер

`Источник → Архитектура процессов → AS-IS → Анализ и TO-BE → Моделирование и QA → Клиентский пакет`

Используются четыре роли:

1. **Coordinator / Process Architect** — управляет реестром, границами и сквозной архитектурой.
2. **AS-IS Analyst** — восстанавливает подтверждённый фактический процесс без оптимизации и домыслов.
3. **Improvement / TO-BE Architect** — диагностирует потери, проектирует организационный TO-BE и фиксирует причины преобразований.
4. **Modeler / QA** — превращает утверждённую логику в BPMN/Visio/PDF и приложения, не изменяя бизнес-логику.

## Уровни представления

- **L0** — Process Landscape роли/подразделения или верхнеуровневая карта цепочки ценности.
- **L1** — сквозной межфункциональный процесс с несколькими ролями.
- **L2** — подробный подпроцесс.
- **L3** — используется только при объективной необходимости.

Один процесс может входить в несколько `views`, но существует как один канонический объект в `processes/`.

## Главное требование прослеживаемости

Для каждого существенного элемента должно быть возможно пройти цепочку:

`источник → AS-IS → проблема/ограничение → решение → TO-BE → элемент схемы → приложение`

AS-IS не перезаписывается TO-BE. История изменений и причины преобразований сохраняются постоянно.
