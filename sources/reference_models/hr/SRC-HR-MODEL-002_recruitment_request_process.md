# SRC-HR-MODEL-002 — существующая схема «Заявка на подбор»

Тип источника: существующая пользовательская процессная схема.

Статус модели (AS-IS / TO-BE / approved / draft): UNKNOWN — не интерпретировать без подтверждения.

Оригинальный артефакт: `Заявка на подбор (1)(1).png`, предоставлен пользователем в чате 2026-08-21.

Ниже — текстовая нормализация содержимого изображения для использования агентами. Она не заменяет оригинальную графическую компоновку и не исправляет бизнес-логику схемы.

## Дорожки

1. Руководитель подразделения
2. Генеральный директор

## Поток

- Start: `Возникла потребность в сотруднике`.
- `1.1 Оценить фактическую загрузку подразделения и рассчитать потребность в сотруднике` — роль: Руководитель подразделения.
  - связанный документ: `Таблица оценки загрузки (расчёт потребности)`.
- `1.2 Принять решение о необходимости введения позиции / заполнения вакантной штатной единицы` — роль: Руководитель подразделения.
  - на схеме связан документ: `Приказ / распоряжение / распределение функций / должностная инструкция`.
- `1.3 Определить функции и задачи будущего сотрудника` — роль: Руководитель подразделения.
- `1.4 Сформировать заявку на подбор, включить в неё обоснование потребности и перечень функций и направить на согласование генеральному директору` — роль: Руководитель подразделения.
  - связанный документ: `Заявка на подбор (с обоснованием потребности и перечнем функций)`.
- `1.5 Рассмотреть заявку на подбор` — роль: Генеральный директор.
- Gateway: `Результат рассмотрения заявки`.
  - `Требуется доработка` → `1.6 Сформировать и направить замечания и рекомендации по доработке` — роль: Генеральный директор; далее возврат к доработке содержания заявки/функций согласно схеме.
  - `Согласовано` → `1.7 Направить согласованную заявку HR` — роль: Руководитель подразделения → End `Заявка направлена HR`.
  - `Не согласовано с подбором` → End `Подбор сотрудника не согласован`.

## Архитектурное наблюдение источника

Схема имеет собственный trigger (`Возникла потребность в сотруднике`) и самостоятельный результат (`Согласованная заявка направлена HR` либо отказ в подборе). Поэтому Agent 01 должен отдельно проверить ее границу относительно `HR-RECRUIT-001`, а не автоматически считать поступление заявки самым первым событием общего E2E.

Это не предрешает уровень L1/L2: окончательная классификация должна учитывать канонические правила границ и место процесса в общей HR-архитектуре.
