# Views

`View` — это представление канонических процессов, а не отдельная копия бизнес-логики.

Поддерживаемые типы:

## ROLE_LANDSCAPE
Отвечает: «В каких процессах участвует конкретная роль?»

Пример: функциональная карта главного бухгалтера.

## DEPARTMENT_LANDSCAPE
Отвечает: «Какие процессы и направления деятельности находятся в контуре подразделения?»

Пример: карта кадровой службы.

## END_TO_END
Отвечает: «Как достигается единый бизнес-результат через несколько ролей и подразделений?»

Пример: потребность в сотруднике → подбор → прием → выход → адаптация.

## Правила

- View хранит только ссылки на `process_id`.
- Переименование процесса обновляется в одном каноническом месте.
- L0 view может ссылаться на L1; L1 — раскрывать блоки через L2.
- На view не дублировать детальные шаги из process package без необходимости.
- При входе/выходе между процессами использовать стабильные IDs.

Шаблон: `templates/view.yaml`.
